# Humanizer-Bilibili — B站知识口播去 AI 味指南

> 底座：`blader/humanizer` SKILL.md (35 patterns + Wikipedia:Signs_of_AI_writing)
> 定位：中文知识分享口播的**文案质量门**，跑在 `script → tts_selector` 之间，不新增管线。

## 何时用

- 任何要合成中文 TTS 的知识稿：`animated-explainer` / `repo-to-video` / `animation` / `talking-head` 的 `script` artifact
- 字幕/标题/简介等 `publish_copy` 的 AI 腔清理（轻量版）
- 用户说“帮我人性化一下”“去AI味”“改成口播稿”

**不用的情况**：纯素材剪辑 `clip-factory` / `fabric-showcase` 无旁白；代码/数据/链接不改（同原版 file mode）。

## 工作流（必读）

1. **标 AI 模式**：对照下表 38 条扫一遍稿子，打标
2. **初稿重写**：可缩/扩/并段，但**事实一个不增不减**（人名/数字/日期/引用必须来自源稿或用户），缺细节就追问
3. **口播自检**：大声读一遍，问两句
   - “还有哪句像 AI 念稿？”
   - “有没有加/丢事实？”
4. **TTS 化**：过 `§36-38` 口播规则，单句 ≤28 字、清符号、补停顿
5. **返回**：粘贴模式给 `草稿 + 问题清单 + 终稿`；文件模式只写终稿到文件并给摘要

写入声线：如用户给了过往 B站稿样本（2-3 段），优先模仿样本的句长/口癖/感叹词节奏，覆盖默认风格。样本中有的 `——` 保留其频率，否则按 `§14` 清除。

## 38 条模式

### 内容类（1-6，原版直用，加强中文例）

| # | 问题 | 中文高频词/句式 | 处理 |
|---|---|---|---|
| 1 | 夸大重要性 | 具有里程碑意义/标志着新时代/深刻影响/至关重要 | 删空话，留事实：`1989年成立，是西班牙分权改革的一部分` |
| 2 | 堆名气 | 被 NYT/BBC/人民日报报道，粉丝 50万 | 只留有用溯源，其余删 |
| 3 | 浅层 -ing/的 分析 | `体现了/彰显了/反映了...` 的万能收尾 | 删，`寺庙是蓝绿金三色，本想呼应德州野花与墨西哥湾` |
| 4 | 销售话术 |  nestled/令人叹为观止/活力之都/丰富底蕴 | `阿拉马塔是贡德尔地区的一座城镇` |
| 5 | 模糊信源 | 专家认为/有研究表明/据观察 | 点名真实源，否则删 |
| 6 | 套路展望 | 尽管面临挑战...未来可期/持续向好 | 删，留 `该区常堵车、缺水` |

### 语言类（7-13）

| 7 | AI 高频词 | **中文新增**：此外/综上所述/值得注意的是/本质上/深入探讨/赋能/抓手/落地/闭环/底层逻辑/具有重要意义/不可或缺/至关重要/深刻 | 换成人话：`此外→另外 / 深入探讨→具体看看` |
| 8 | 回避 是/有 | 作为...存在/担当...角色/拥有 | `是/有` |
| 9 | Not X but Y | 不是...而是... / 不只是 X，更是 Y | 直接说 Y：`重鼓点让气氛更凶` |
| 10 | 强制三联 | 创新、灵感与洞察 | 按需数量 `有分享和讨论，中间也留了交流时间` |
| 11 | 换名/句首重复 | 主角/主人公/英雄 反复；`她说...她说...她说...` | 统一一名，合并句 |
| 12 | 伪 from X to Y | 从 Big Bang 到暗物质 | 列清：`讲了大爆炸、恒星形成、暗物质假说` |
| 13 | 被动/缺主语 | 无需配置/结果已自动保存 | 补主语：`你不用配文件，系统会自动保存结果` |

### 风格类（14-19,26-35）

| 14 | 破折号 | `—— / — / --` 口播读不出 | 全改为 `，`/`。`/`（ ）`；样本有则按样本频率保留 |
| 15 | 过度加粗 | `**OKR** **KPI**` | 去 `**` |
| 16 | 加粗小标题列表 | `- **性能：** ...` | 改连贯句 |
| 17 | 标题全大写 | `战略谈判与全球合作` Title Case | `战略谈判与全球合作` 句首大写 |
| 18 | Emoji | `🚀 💡 ✅ ✨` | 口播稿全删，封面标题除外 |
| 19 | 弯引号 | `“ ”` | TTS 前统一 `"` |
| 26 | 连字符堆砌 | `跨职能/数据驱动/端到端` 满篇 | 名词前保留 `高质量报告`，句尾去 `报告质量很高` |
| 27 | 伪深刻 | 问题的本质是/真正的关键在于 | 直接说：`关键看团队能否改习惯` |
| 28 | 预告下一句 | 让我们一起看看/接下来带大家/废话不多说 | 删，直接上内容：`Next.js 在三层做缓存` |
| 29 | 标题复述 | `## 性能\n速度很重要。\n...` | 删复述句 |
| 30 | 写旧版 | 之前用 O(n²) 遍历，现改用... | 只说现在：`用哈希表 O(1) 查` |
| 31 | 强制金句/碎句 | `它没有偏好。没有先验。没有怀旧。` | 改自然长短句 |
| 32 | 公式化格言 | 对称是信任的语言 | 改具体：`对称布局让人觉得更可预测` |
| 33 | 假坦诚开场 | 老实说/说实话/ Honestly? | 删，直接答 |
| 34 | 回应不存在的质疑 | 这不是说文档不重要/别误会 | 删防御，只留 `问题是 agent 能否在执行时用上指令` |
| 35 | 拒绝假选项 | 本可重启服务轮转，但会掉线... | 删假选项：`轮转在原地完成，客户端无感刷新` |

### 口播新增（36-38，B站/TTS 专用）

| 36 | 呼吸 | 单句 >28 字、无逗号的长难句 | 拆句，逗号处可停顿；每段 2-4 句，交替长短 |
| 37 | 书面→口语 | 因此/从而/进行/得以/旨在 | `因此→所以 / 进行分析→来分析 / 得以实现→就能做到`；术语不动 |
| 38 | B站人格 | 通篇中立无“我”、无例子 | 知识稿保留 `我试过/说人话就是/举个栗子/我踩过的坑是`，但不编新案例数据；参考/法律稿保持中立 |

### 聊天机器人（20-22）/ 填充（23-25）

| 20 | 残留话术 | 希望对你有帮助/需要我展开吗 | 删 |
| 21 | 知识截断+猜测 | 截至2024年/由于资料有限，可能... | `现有资料未记载` 或删，不猜 |
| 22 | 过度讨好 | 太棒了/你问得很好 | 直接答 |
| 23 | 填充 | 为了达到...目的/在...情况下 | `为了→为 / 由于...→因为` |
| 24 | 堆限定 | 可能也许大概 | `可能` |
| 25 | 空洞乐观结尾 | 未来可期/前景光明 | 删，落在最后一个事实或实操建议 |

**误判保护**（同原版）：单条不算证据。专业润色/单次 `然而`/单 `——`/单句强调/刻意排比 `她来。她看。她征服。` 需多条共现再改。引号内、代码内、标题内不改。

## 口播 TTS 适配清单（过 `voxcpm_tts` 前必检）

- [ ] 无 `—— — ** Emoji “ ”`，`...` → `。`
- [ ] 单句 ≤28 字，长句已拆
- [ ] `is/are` 已用 `是/有`，被动已补 `你/系统`
- [ ] 无 `首先/其次/最后` 三连，无 `让我们一起` 预告
- [ ] 每段有 1 个具体细节（数字/地名/人名/操作），无编造

`voice_description` 建议（仅第1段）：`耐心的知识讲解员，语速稍慢，亲切像朋友聊天`（见 `.agents/skills/voxcpm-tts/SKILL.md`）。

## 返回格式

- **粘贴**：`草稿 → 剩余问题（3-5 条）→ 终稿`
- **文件**：`humanize docs/script.md` 只改 prose，保留 `code/frontmatter/data/链接`
- **嵌入**：被 `script-director` 调用时只回终稿

## B站知识稿示例

**改前（AI 腔）：**
> 让我们一起深入探讨为什么高铁能跑 350km/h。首先，空气动力学至关重要。此外，轨道技术发挥了不可或缺的作用。综上所述，中国高铁的成功是多方面因素共同作用的结果，未来可期。

**改后：**
> 高铁跑到 350km/h，靠的不是单一黑科技，是三件事一起抠细节。第一，车头。把车头削得更尖，风阻就能降 10% 以上，我在风洞视频里看到，旧款车头后方的涡流像小尾巴，新款直接被拉平了。第二，轨道。无砟轨道把每块钢轨焊成一根，少一次接头就少一次颠簸。再加上供电和调度一起配合，才把速度稳住。说白了，就是把每个环节的 5% 优化叠起来。
