# ADR-003: Auto-Dub 逐句时长对齐与分句合并决策

- **状态**: Accepted（D3 对齐闭环被 ADR-004 部分取代；D1/D2/D4/D5/D7 保留）
- **日期**: 2026-08-09
- **修订**: 2026-08-12 — 前提「IndexTTS2/VoxCPM 均无语速参数」因 IndexTTS-2.5 引入 `duration_factor` 而失效。D3 的「事后测量+逐句 atempo」对齐方式升级为「Duration Factor 粗调 + Atempo 微调」（双次合成），见 ADR-004。
- **决策者**: 用户 + AI Agent (grill-with-docs session)
- **影响范围**: Auto-Dub 流水线（`apps/auto-dub/` 与专属校准工具）

## 背景

用户观察到成品中存在两类问题：① 英文原句被拆成多条碎字幕（"明明是一句却分成几句"）；② 中文配音时长与原语音不一致。

实测 29 个项目、6734 句数据：中位 中文时长/原文时长 0.96（整体近似），但超 ±15% 误差的句子占 66.5%，超 ±30% 占 37.1%。现状机制（字数预算 + 全局 atempo ±5% + 缩短重翻）只保证整体漂移收敛，不保证逐句一致。

两个 TTS 引擎（IndexTTS2、VoxCPM）均无语速参数，合成时长不可预测，逐句精确对齐只能靠事后测量 + 变速。

## 决策

### D1: 转录后规则合并为原句（Utterance）

Whisper Segment 按「句末标点（`. ! ?`）+ 相邻段时间间隙 < 0.5s + 单句上限 15s」合并为 Utterance。不做 LLM 语义合并，保证确定性、零额外成本、可验证。Utterance 是字幕与对齐的锚点单位。

### D2: 字幕单位与合成单位分离

一段 Utterance = N 个合成子块（Chunk，按中文标点切）= 1 条字幕。每个 Chunk 一个 WAV、各自变速；SRT 仍按 Utterance 合并为一条。打破原有「一段 = 一 WAV = 一 SRT」三元绑定（仅在本方案内，原绑定约束以 Utterance 为边界重新定义）。

### D3: 逐句对齐闭环

合成 → 实测时长 → 逐句 atempo 变速 → 校验。变速上限 ±5%（Tempo Budget），超限句子不强行变速，回退 LLM 重翻改写译文长度（Retranslation）。对齐容差 ±15%（Alignment Tolerance）。

### D4: 排队间隔归入变速目标

变速目标时长 = 原句时长 − 100ms（Queue Gap），使句尾贴合原句 end，避免逐句对齐后 100ms 硬间隔累积成漂移。

### D5: 验收标准

新处理视频逐句达标率 ≥ 95%（±15% 内）、单句最长偏差 < 0.5s、碎句率（字幕 < 2s）归零。达标率统计排除 Inherently-Long Sentence（见 D7）。旧成品不动，仅影响新处理视频。

### D7: 短回应句豁免

访谈中原句 < 1s 的极短回应句（"对。""没错。"「嗯嗯」），中文朗读时长物理上不可贴合原句，变速与重翻均不可达。标记为 `inherently_long`（Inherently-Long Sentence），允许超对齐容差，且不参与验收达标率统计，避免浪费变速/重翻算力。合并规则优先将此类句子并入相邻句，仅在无法并入时豁免。

### D6: 改动封闭范围

只动 Auto-Dub 流水线代码（转录后合并、逐句变速、SRT 合并）与专属校准工具；TTS 引擎、混音 100ms 串行排队算法、OpenMontage 通用工具层不动。

## 后果

- **正面**: 字幕与语义单位一致，逐句时长贴合原语音，消除碎句；方案确定性高、可逐句校验。
- **负面**: 变速 5~15% 区间的句子全部走 LLM 重翻，重翻调用量上升；±5% 变速对极快/极慢语速句可能引入轻微听感变化。
- **风险**: 逐句对齐依赖 cps 校准精度与 TTS 时长可测性；合并规则（0.5s 间隙/15s 上限）为经验阈值，需按实测定参。
