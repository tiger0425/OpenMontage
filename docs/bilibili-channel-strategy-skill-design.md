# Bilibili 频道运营策略 Skill — 技术设计文档

> 状态：待评审 | 作者：OpenMontage | 日期：2026-08-08

> 评审通过后据此实现 skill；本文档留存为该 skill 的权威技术规格。

---

## 摘要

设计一个中文、可扩展的 B 站频道运营策略 skill（Layer 3 / Tool skill），
将经 `/grilling` 会话确认的三号矩阵定位、标题/封面/简介规范、发布与护持期
SOP、数据观测机制固化为 agent 可读的运营规则书。该 skill 不修改
auto-dub 流水线代码，只在「选片 → 定标题/简介/封面 → 发布 → 复盘」的
人工决策环节被 agent 读取并套用。

---

## 背景

用户运营一个 B 站账号矩阵（现有主号 + 两个新建号），基于 auto-dub 流水线
（YouTube 下载 → Whisper 转录 → LLM 翻译 → VoxCPM/IndexTTS 配音 →
FFmpeg 压制）批量产出中文配音视频。现有问题：

1. **单号内容漂移**：免费AI / AI搞钱 / AI知识 / GitHub 项目四类方向混发，
   B 站标签被推荐系统打散。
2. **收藏 >> 关注**：内容实用但无"关注理由"，收藏不产生收益。
3. **运营经验不可复用**：定位、标题公式、发布时间等规则散落在会话中，
   换会话/AI 工具即丢失。

`/grilling` 会话已收敛出完整决策树（见附录 A），本文档将其规格化。

---

## 目标

- 固化三号矩阵定位与差异规则（C 主号 / A 赚钱号 / B 开发者号）。
- 提供标题公式、简介模板、封面验收规范的**可执行规则**。
- 定义发布时段、护持期 SOP、弹幕种子模板。
- 提供可扩展结构：新增号/新增方向无需改通用规则。
- 明确与 auto-dub 工作流的 5 个对接点（仅决策层，不改代码）。

## 非目标

- 不修改 `apps/auto-dub/` 任何代码、`bin/auto_dub.py`、config.yaml 结构。
- 不做 AI 自动发布/自动回复（发布与护持期均为人工作业，skill 只给规则）。
- 不生成媒体资产本身（标题/封面/简介仍由 auto-dub 底稿 + agent 改写完成）。

## 核心数据模型：号档案（Channel Archive）

每个账号一个档案，为 SKILL.md 内的标准章节。Schema 如下：

```yaml
channel:
  id: C                    # 账号标识（C/A/B/D…）
  name: "<现主号频道名>"     # 实际频道名（C 号不更名）
  status: active           # active | standby | archived
  positioning:             # 定位一句话（唯一，决定选题与封面）
    one_liner: "国外AI大V视频中文翻译"
    audience: "泛知识人群（AI 开发/应用/行业动态）"
    differentiation: "资讯型：大V观点/演示/访谈翻译，非自制教程"
  content_pool:            # 选题池规则（对接 auto-dub 各池）
    source: "大V视频列表链接（找到即投递）"
    routing: "C池 = 用户提供的视频列表链接"
  cadence: daily           # 发布节奏：daily | weekly3-4 | weekly1-2
  publish_time: "19:30 定时发布"
  cover_style: "大V资讯风（人脸/原片截图+大字标题≤8字）"
  series_rule: '前缀编号，如 "AI大V翻译 #21"'
  follow_hook: "每周三更新一期免费AI实战 / 关注不迷路"
  metrics_target:          # 成功指标（相对值，见 §7）
    interaction_trend: "逐条上升"
```

### 三号档案初始值（评审确认）

| 字段 | C 号（现主号 1500粉） | A 号（新建） | B 号（新建） |
|------|----------------------|-------------|-------------|
| positioning | 国外AI大V视频中文翻译 | 免费AI + AI搞钱 | 开发者省钱实操 + 开源项目盘点 |
| audience | 泛知识人群 | 省钱小白→赚钱人群 | 进阶开发者 |
| differentiation | 资讯型（大V演示/观点/访谈） | 省钱+赚钱双主线 | 实操型（教程/项目），区别于 C 资讯型 |
| content_pool | 大V视频列表链接 | 频道 + 关键词搜索 | GitHub 热榜 |
| cadence | daily | weekly 3-4 | weekly 1-2 |
| publish_time | 19:30 | 19:00-22:00 随质量 | 19:00-22:00 随质量 |
| cover_style | 大V资讯风 | 省钱红字风（"免费！""省$20"） | 硬核深色风（代码/终端截图） |
| series_rule | AI大V翻译 #N | 免费AI实战 #N | 开源黑科技 #N |

## SKILL.md 章节结构（实现蓝图）

```markdown
---
name: bilibili-channel-strategy
description: 三号矩阵运营规则书…（触发词见 §8）
---

# Bilibili 频道运营策略

## 1. 系统概述与使用方式
   - 本 skill 是给 agent 读的规则书；用户喊触发词时读取对应章节
   - 与 auto-dub 的关系：不碰代码，只在决策环节生效

## 2. 通用规则（改一次，全员生效）
   ### 2.1 标题公式
       【分区】好奇钩子 + 具体细节 + 情感锚
       示例: 【硬核科普】为什么中国高铁能跑350km/h？答案让我震惊
       规则: 不标题党/不超字数/保真（翻译号不得虚构原视频内容）
   ### 2.2 简介模板
       首行钩子 + 3-5 条要点 + 关注引导 + 相关标签
   ### 2.3 封面验收 Checklist
       [ ] 大字≤8字（中文）  [ ] 高对比  [ ] 人脸/表情或关键视觉
       [ ] 通过滚动测试（20图里能被一眼看到）  [ ] 颜色匹配号风格
   ### 2.4 发布时间规则
       19:30 定时发布，20:00 进推荐，匹配弹幕峰值
   ### 2.5 护持期 SOP（发布后 30 分钟）
       回复全部评论 + 置顶一条引导 + 动态同步一条
       ★ 相对指标：零互动残留优先于绝对数字（不追 50 赞 20 评）
   ### 2.6 弹幕种子模板（可选，10-15 条）
       时间点触发设计表 + 前 1 小时播种策略

## 3. 号档案
   ### 3.1 C 号档案
   ### 3.2 A 号档案
   ### 3.3 B 号档案
   ### 3.4 新增号模板（复制即用，勿改通用规则）

## 4. 数据观测表
   每条视频记录: 播放 / 收藏 / 关注增量 / 三连率 / 完播趋势
   每两周: 判断选题漂移 / A/B 是否加投 / C 号方向是否延续

## 5. 与 auto-dub 工作流对接（5 个插入点）
   | 流水线环节 | 对接动作 |
   | 选片(人工)  | 按号档案选题池挑 + 打标分流 C/A/B |
   | 标题        | 套 §2.1 公式改写 |
   | 简介        | 套 §2.2 模板生成 |
   | 封面        | 对照 §2.3 Checklist 验收/重做 |
   | 发布        | §2.4 时段 + §2.5 护持期 + 弹幕种子 |

## 6. 更新协议
   跑两周出真实数据后，向用户确认哪些号档案要改 → 更新本文件
   用户说"更新 skill"即触发此流程
```

## 对接点明细（与 auto-dub 的边界）

| # | auto-dub 环节 | 谁执行 | skill 角色 | 变更面 |
|---|---------------|--------|-----------|--------|
| 1 | `scan` / `filter` | 流水线 | 不干预 | 无 |
| 2 | **选片（人工）** | 用户+agent | 按号档案选题池挑 + 打标 | 决策 |
| 3 | **标题** | auto-dub 出直译 → agent 改写 | 套标题公式 | 决策 |
| 4 | **简介** | agent 生成 | 套简介模板 | 决策 |
| 5 | **封面** | auto-dub 生成 → agent 验收 | 对照 Checklist，必要时重做 | 决策 |
| 6 | 混音/压制 | 流水线 | 不干预 | 无 |
| 7 | **上传/发布** | 用户 | §2.4 时段 + §2.5 护持期 | 决策 |
| 8 | **复盘** | 用户+agent | §4 观测表 | 决策 |

> 原则：skill 永远不改 auto-dub 的输入/输出文件结构与命令行契约。

| 用户说 | agent 动作 |

| "复盘 / 数据怎么样" | 读 §4 → 按观测表分析 |

| "更新 skill" | 更新号档案/通用规则 |

## 扩展机制

### 新增号（D 号）
1. 复制 §3.4 新增号模板。
2. 填：id / positioning / audience / content_pool / cadence / cover_style。
3. 通用规则（标题/封面/发布/护持期）自动适用，不改。

### 现有号新增方向
- 仅在该号档案的 `content_pool` 或 `positioning` 字段追加规则。
- 不改 §2 通用规则。

### 号下线
- 档案 `status: archived`，保留记录不删除。

## 数据观测表设计（§4 落地格式）

每条视频记录一条（建议放项目 `projects/bilibili-ops/observation.csv` 或
用户自建表格，agent 负责每次复盘填充/读取）：

```csv
date,channel,video_title,views,likes,coins,favorites,followers_delta,completion_note,source_pool
2026-08-09,C,AI大V翻译 #21,580,23,5,41,+12,中段流失,大V列表
```

复盘规则：
- **C 号**：关注增量是否逐条上升（趋势，非阈值）；选题是否漂移出定位。
- **A/B 号**：前 10 条跑完看是否有进入二线推荐池（约 1 万播放）的迹象；
  无迹象 → 讨论是否换选题或降频。

## 验证策略

1. **结构验收**：SKILL.md 含 §1-§6 全部章节；号档案含 C/A/B/模板四段；
   对接点表 5 行齐全。
2. **触发验收**：用 §8 触发词表逐条走查，agent 能定位到对应章节并给出
   基于规则的回答（而非泛泛建议）。
3. **实测验收（金标准）**：下一条 C 号视频走完整流程（选片→标题→简介→
   封面→发布→护持期），用户对输出点头 → skill 生效；摇头 → 当场改 skill。
4. **扩展验收**：模拟新增 D 号，确认仅复制模板即可，通用规则无改动。

## 风险与约束

| 风险 | 缓解 |
|------|------|
| 发布时间数据源为第三方经验文，非官方算法 | 以用户实测数据为最终依据；skill 标注"初值，按观测调整" |
| 收藏>关注问题可能随内容变化 | 观测表持续跟踪关注增量趋势 |
| 三号封面风格冲突 | 三号档案 cover_style 已差异化，互不混用 |
| 用户日更投入护持期时间压力 | 若护持期无法每日执行，C 号降频至周 5 更（skill 内已注明触发条件） |
