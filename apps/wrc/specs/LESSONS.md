> 来源：2026-08-23 第二单（Citroën Xsara 悬挂漏洞，wrc-m8uwKEiiuq8）全流程实战踩坑。
> 用途：后续任何会话跑 wrc 管线前必读，避免重蹈覆辙。

## 1. 管线级 Bug（已修复，勿回退）

### 1.1 资产复制"已存在则跳过"导致重渲染用旧资产
- **现象**：改完 frames.json（如片段时长 8s→15s）重跑 `render-video`，渲染用的仍是 compose/ 里**残留的旧资产**——因为 `bin/wrc.py` 复制资产时 `if not exists` 才拷贝。
- **危害**：片段时长/帧内容改了等于没改，肉眼排查半天才发现渲染根本没用新文件。
- **修复**：`bin/wrc.py` 资产复制改为**总是覆盖**（`shutil.copy2` 无条件执行）。
- **教训**：重渲染前，先核对 `compose/<ep>/assets/` 里关键文件的修改时间和内容（`ffprobe` 时长），确认渲染用的是新版。

### 1.2 preflight 卡死
- `bg_remove`（rembg）工具的 `get_status()` 会挂起导致整个 `provider_menu_summary()` 卡死（疑似首次运行下载模型）。
- 绕法：探针脚本用 daemon 线程 + 超时逐个测 `get_status()`，定位挂起工具后打补丁跳过它。
- 属 OpenMontage registry 层问题，与 wrc 管线无关，但会挡 preflight。

## 2. 语音（TTS）经验

### 2.1 年份读法（本单核心教训）
- **裸数字 + 顿号**（"2003、2004、2005"）→ IndexTTS 读法不对（用户反馈"按年份说话"）。
- **数字 + 年**（"2003年、2004年、2005年"）→ 正确按年份朗读（"二零零三年/二零零四年/二零零五年"）。
- 规律：单年份带"年"（"1995年""2006年"）一直读得对，出问题的都是**无"年"的年份列表**。
- **结论**：文案里年份一律写"数字+年"，列表也逐个加"年"。

### 2.2 语音验证闭环（重渲染前必做）
- **Whisper 回听**：重配某段语音后，用 `tools/analysis/transcriber`（或 `bin/wrc.py script` 同款）转录该 wav，比对文本确认读法。
  - 产物：`assets/sN_transcript.json`（注意 res.data.text 可能是空的，读文件）。
  - 本次验证：s7.wav → Whisper 听到"2003年、2004年、2005年…"，确认按年份朗读。
- **只重配单段**：删除 `assets/sN.wav` 后跑 `render-assets`，TTS 只补缺失的那段（其余跳过），再全量 `render-video`。
- **代价控制**：语音验证通过后再派 render-video（30-40 分钟），别让全量渲染白跑。

### 2.3 品牌/人名读法（厂家名称用中文）
- 英文品牌名（Citroën、Xsara、Loeb 等）让 IndexTTS 直接念会读得怪/念错——**配音文案里一律写中文品牌名**：Citroën→雪铁龙、Xsara→赛纳、Peugeot→标致、Toyota→丰田、Loeb→勒布。
- **只改配音文案**（narration），屏幕展示文字（hook/title/display）保留英文品牌名，视觉上更专业。
- 验证注意：Whisper 转写中文品牌名常有**繁体/同音字差异**（雪鐵龍/薛鐵龍/血體龍、散納/赛纳）——按**音节**判断，不要因转写差异误判语音错误。

### 2.4 中文破折号「——」会被逐字读成"减、减"（2026-10-14 三菱片实测）
- IndexTTS 把旁白里的 **em dash「——」当成两个独立字符**，直接念出来就是"减、减、"。用户听到后报"被读成减减了"。
- **配音文案里禁用「——」**，改用自然停顿标点：
  - 转折停顿 → `。` 或 `，`
  - 补充说明 → `，`
- **自检一行搞定**：`json 文本里 count("——") == 0`（注意也检查 narration，不只 hook）。
- 换掉之后**必须删掉对应 `assets/sN.wav` 重配**，否则成片还是旧语音。

### 2.5 「主」字会被读成二声 zhú（2026-10-15 三菱回归片实测）
- 用户报「主这个字有的地方读错了」。Whisper 回听坐实：s5 的 **「主动传动系统」被念成「竹东传动系统」**。
- 同一个词在 s4/s6 侥幸读对 —— **不是稳定的错，是随机翻车**，不能靠运气。
- **对策：配音文案里回避「主」字**，换同义表达：
  - 主动传动系统 → **电子传动系统**（也更贴源片原文 computerised systems）
  - 主力车手 → **头号车手**
  - 主场作战 → **家门口作战**
- 自检：`narration.count("主") == 0`。

### 2.6 「三菱」紧邻年份 → 四个 líng 叠音糊成一片（同日实测）
- 用户报「第一句说到三菱后面就听不太清」。根因不是读错字，是**连读叠音**：
  `三菱2002` = sān-**líng**-**èr-líng-líng**-èr，菱的 líng 与「二零零二」的三个 líng 连成一串，听不出边界。
- Whisper 回听直接当成数字：把「上集说到三菱2002年底」听成「**三零零二零零二**年底」。
- **对策：调语序，让品牌名与数字之间隔开**（隔一个动词/助词或把年份提前）：
  - 上集说到三菱2002年底退出 → 上集说到，**2002年底三菱**退出
  - 这是三菱2001年以来最好的成绩 → 这是**2001年以来三菱**最好的成绩
- **通用自检**：`re.search(r'三菱[0-9]', narration)` 必须为 0；同类叠音风险也检查其他以 -ng 结尾的品牌名（如「大众」「通用」）后紧跟数字。
- 注意区分：Whisper 把「三菱」转写成「三零/30」是**同音字转写差异**（LESSONS §2.3），属正常，不是错误 —— 真正要修的是**后面紧跟数字**时的叠音。

### 2.7 句子连读太紧 → 用句号拆短（同日实测）
- 用户报「有些句子之间连得太紧，听不清」。
- **IndexTTS 的停顿长度由标点驱动**：逗号≈短停、句号≈长停。长逗号链会读成一片。
- 对策：把逗号长链**拆成句号短句**（本片每幕句号数从 6 提到 7–9）。
- **客观验收用静音检测**，不要靠 Whisper 标点（它自己会重排标点，不可靠）：
  ```powershell
  ffmpeg -hide_banner -i sN.wav -af "silencedetect=noise=-38dB:d=0.15" -f null -
  ```
  健康值参考（本片实测）：每幕 **11–18 处停顿**、总停顿占 **16–25%**、最长停顿 **0.35–0.49s**。

## 3. 画面/抽帧经验

### 3.1 源视频白底卡片风 → 白卡泛滥
- WRC Explained 这类源视频大量画面是**白底图文卡**（图解/FIA 标/品牌卡），白像素占比 75%~99.8%。
- 直接当媒体卡放大展示 = 屏幕上出现巨大的白框，挡住背景 → 用户抱怨"挡住其他内容"。
- **对策**：
  - 抽帧后用**白像素占比**量化（>50% 就要警惕，>90% 基本是空/近空卡）。
  - 某些时间戳是**空白过渡帧**（如 324s 附近 3 帧里第 1 帧几乎全白）——核验时选清晰的帧（325/326）。
  - 技术幕可以接受白底图解，但**不要**让同款白卡反复出现；用**车内镜头/车队合影/动态片段**调剂多样性。
- **重复度审计**：合并分集时容易把同一批图反复用（本单 Xsara ×4、图解 ×4、FIA ×5）。成片前数一遍每张图出现次数，目标 ≤3。

### 3.2 视觉核验工具
- `.agents/skills/minimax-m3-vision/scripts/analyze_media.py` 批量核验候选帧；**必须 `PYTHONIOENCODING=utf-8` + 输出落盘**（控制台 GBK 乱码）。
- 模型空间描述不可靠（"人像/照片卡"多次幻觉）——**像素级方法更可信**：
  - 跨幕逐像素方差找"卡住"元素（低方差区域）；
  - 连通域（scipy.ndimage）量卡片/白色区域精确 bbox；
  - 卡片区 vs 资产图相关性匹配（相似度）。

### 3.3 模板行为验证（快迭代）
- 完整成片渲染 30-40 分钟，**改模板前先用 3-6 秒最小 composition 渲染验证**（10 秒内出片），确认 CSS/时间窗行为再全量。
- 本单靠此确认：div 包裹卡片高度正确（624×353 vs 异常 790）、video 带 data-start 后场景切换即消失。

### 3.4 品牌审计：抽帧点"看着像"不算核过，必须全片扫一遍（2026-10-14 三菱片实测）
- **事故**：只核了用户点名的那一幕（s4）的车身品牌，没核其余。结果 19 段 clip 里 **6 段挂错车**：
  丰田 Celica（讲三菱的车）、福特 Sierra、福特 Escort、尾段串进斯巴鲁 + 日期卡、山谷航拍（全程看不见车）。
- **根因**：抽帧点是"按时间戳挑的"，不是"按品牌挑的"。源片是蒙太奇，同一个 10s 窗口里可能换 2~3 台车；**起点是三菱不代表整段是三菱**。
- **正确做法（成片前必做）**：对**每一条** clip 抽 3 帧（15% / 50% / 85%）拼成带标签的对照图，逐张过一遍。19 段 = 19 张图，一次看完。
- **窗口边界还要再扫一遍**：起点和中点是三菱不代表结尾是。三菱片实测三处脏尾：
  - 戈蓝雪地段 41.5s 起转模糊 → 切到 41.0s
  - 红色 Evo 段 494s 起是 "October 2001" 日期卡 → 起点前移到 480.0s
  - Lancer WRC 段 794s 起车退到远处看不见 → 切到 793.5s
  - 精确定位用**0.5s 步进扫尾段**拼图，一次看清切点。
- **旁白提到的车可以出现**：讲"马基宁转投斯巴鲁"那一幕出现斯巴鲁是对的；讲三菱的幕出现别家车才是错。判断标准是**这一幕的主角是谁**。
- **用户说"这个应该本来就是 A"时要立刻自查有没有搞反**：本单我以为要换 s4，用户指的是 s0——**先定位旁白原句出现在哪一幕**，别按自己的猜测动手。

## 4. 分集/合并经验

- 单集规格上限约 3 分钟（10 幕 × ~18s）。用户要 4-6 分钟 → 拆上下集；用户要"合成一集" → 合并为 10 幕单集（~2.5-3 分钟），接受信息密度下降。
- 合并时**画面会重复**（两集的素材池相同）→ 按 §3.1 做重复度审计。
- `frames.json` 是**全项目单文件**（不是每集一个），资产名必须全项目唯一（e1_/e2_ 前缀）；scene 字段只用于 render-video 的兜底回填。

## 5. 交付验收清单（成片给用户前）

1. 卡片尺寸/位置：split 媒体卡 bbox 应在媒体区内、不压玻璃卡线（y=1000）；
2. 残留帧：片段场景之后的时间点无静止残留（跨幕方差 / 相邻帧差）；
3. 片段正片：clip 可见窗口播的是片段**开头**（飞跳/车载），不是尾巴（人像/采访帧）；
4. 语音：年份等敏感数字按预期朗读（Whisper 回听）；
5. 边界切换：相邻幕内容差异大（diff > 50 为干净切换）；
6. 音轨：`volumedetect` mean 在合理范围（-20~-30dB 正常）；
7. 水印/封面/标题：package 内容齐全。

## 6. 发布经验（抖音手动上传）

- 本管线产出是**抖音竖屏包**，抖音无 CLI 上传 → **发布前先问用户平台**（抖音手动 / YouTube 可 CLI / 都要）。
- 成品包 `package/<n>/`：`video.mp4` + `cover.jpg` + `title.txt` + `title_alt.txt` + `desc.txt`，直接给用户即可手动发布。
- **标题策略**：主标题是陈述式（"Citroën Xsara：把规则玩成合法"），备用标题是抖音钩子式（"史上最合法的作弊？没被罚还连拿三个冠军"）——推荐抖音用钩子式。
- 简介要含：钩子开场 + 一句主题 + 关注引导 + `#话题` + Footage credit（合规）。
- 封面是 ffmpeg 抽帧 + PIL 绘制（黑底压底 + 标题大字 + 红角标"第1集"），已含在包内。

## 7. 参考视频分析与素材调研（开工前必做）

- **转录**：`yt-dlp --write-auto-subs --sub-langs en --sub-format srt --paths home:<dir>` 拿英文时间轴字幕（注意是 `--paths` 不是 `--sub-outdir`）；管线内 Whisper 转录 `transcript.json` 带分段时间戳，是抽帧时间戳提案的依据。
- **视觉分析**：minimax-m3-vision 批量看关键帧，判内容/风格/白底占比；但**空间描述不可靠**（见 §3.2），定位用像素方法。
- **先看清源视频的"底子"**：WRC Explained 类是白底图文卡风格，直接决定媒体卡选图策略（§3.1），避免做出来才发现画面全是白卡。
- **时间戳提案→候选帧→视觉核验→contact sheet** 的流程见 `frame-selection-spec.md`；contact sheet 随脚本闸门给人审。

## 8. 环境/工具坑（本会话实测）

- **PowerShell 传文件列表**：给 python 脚本传多个文件要用**数组**（`$files` 直接展开），`-join " "` 会变成单个字符串导致脚本当成一个路径。
- **PowerShell 小数文件名**：`"f_$t.jpg"` 里 `$t=46.0` 会生成 `f_46.jpg`（丢尾零），与脚本期望名不符 → 命名前先 `Get-ChildItem` 核对。
- **python -c 内嵌 f-string/转义**在 PowerShell 里反复踩（`{`/`\"` 冲突）→ 复杂脚本一律**写成 .py 文件**再跑。
- **视觉模型批量调用**：一次传太多帧会乱序/幻觉 → 关键判断用**单图调用**；批量仅做初筛。
- **hyperframes CLI**：渲染用 `-o/--output`（`--out` 不存在）；`check` 命令要传项目目录参数；lint 报 `media_missing_data_start` = 视频没给时间窗（模板已修，勿回退）。
- **npm 沙箱**：`npx` 拉包需可写 npm cache，沙箱下 EPERM → 设 `$env:npm_config_cache=<工作区>/.npm-cache`（`bin/wrc.py` render-video 已内置）。
- **GBK 控制台**：中文输出必设 `$env:PYTHONIOENCODING="utf-8"`，复杂结果写文件再读。

## 9. 竖屏搬运/二创：画面清晰度（2026-10-10 埃文斯夺冠片实测）

> 来源：`projects/evans-world-champion-cn`（Redline Syndicate 埃文斯生涯蒙太奇 → 抖音竖屏二创，HyperFrames 手作合成）。
> 用户反馈链：首版"画面不清晰"→ 定位到根因是"竖屏放大"而非编码参数。

### 9.1 竖屏裁切会白白损失 69% 像素（模糊的头号原因）
- 16:9 素材放进 1080×1920 画布用 `object-fit: cover` 时，内容被**放大 1.78 倍**再裁中间竖条：1080p 素材实际只用到中间 **607×1080** 像素，拉伸到 1080×1920。**这就是"剪辑后变模糊"的主因，不是 CRF 问题。**
- **正解：预裁**。素材阶段就用 ffmpeg 把 16:9 裁成 9:16 竖屏落盘，合成层改用 `object-fit: contain`，实现像素 1:1：
  ```
  crop=ih*9/16:ih:(iw-ih*9/16)*<offset>:0,scale=1080:1920:flags=lanczos,unsharp=5:5:0.6:5:5:0.0
  ```
  `offset` 0~1 控制裁切焦点（0.5=居中；双人并排时取 0.62 让主角更完整）。
- 先前的"提高 CRF"（20→18）只解决编码损失，**解决不了放大导致的糊**。

### 9.2 一定要下最高清源片，并核对码率
- YouTube 同一分辨率常有多档码率，`yt-dlp -F` 会看到同是 1080p 有 1563k / 3323k / 5232k 三档；yt-dlp 默认可能选**最低码率**的那条（AV1 1563k）。
- 竖屏裁切是"像素放大镜"，源片分辨率越高收益越大：**能下 4K 就下 4K**（`-f 401` = 2160p AV1），预裁后 1080 宽是真实像素而非插值。
- 出口结论：`4K -> crop 1215x2160 -> lanczos 1080x1920 -> h264 CRF16 preset slow`，车牌/赞助贴纸字级细节可辨。

## 10. 音轨设计：原声、引擎声、BGM（同为 2026-10-10 实测）

### 10.1 剪片段别顺手 `-an`
- 截 broll 时若加 `-an`（去音轨），后续想用原声就得回头重新提取。**要"声音与画面同步"就必须按各剪辑点的源时间戳逐段提取原声**，不能拼一条循环床铺满（那样画面切车、声音不变，完全脱节）。
- 做法：逐段 `-ss <源秒点> -t <片段时长>` 提音频 → `adelay=<时间轴起点ms>:all=1` 定位 → `amix=normalize=0` 叠加。

### 10.2 蒙太奇类源片的"原声"多半是别人的配乐，不是引擎
- 判别方法（逐 1s 帧算 FFT）：引擎 = **低频(90-500Hz)占比高 + 频谱质心低**；音乐 = 质心高、低频占比低。
- 实测 Redline 那条 20 个剪辑点里 **15 个与纯音乐参考同构**（低频占比 0.08~0.26、质心 1700~2600），只有 480s 一段是真引擎+人群（低频占比 0.62、质心 1101、rms 19285）。
- 所以"用原声直通"会变成 **两首歌打架**（源片配乐 + 你的 BGM）。给用户两个可试听版本最稳：
  - **原声直通版**：原声 @0.20 铺底
  - **引擎强化版**：`highpass=110,lowpass=480` + `equalizer f=160 g=7 / f=320 g=5` 滤掉配乐只留引擎，@0.55（本次用户最终选这版）
- 用 minimax/vision 找"领奖台/捧杯"同理不可靠：**批量粗扫会把采访镜头误判成领奖台**，必须加密到每 2-5s 复核（本次粗扫报"有领奖台"，精查 15 帧后全否定）。

### 10.3 BGM 选段与响度
- 选段先做**静音检测 + 能量曲线**：本次 AEROVIPER - Gravity 全曲 273s 无静音，但 0-10s 是淡入（能量 830）、190s 后回落、260s 后尾奏 → 取 **35-141s 高能平台**（mean RMS 5743、起始 10s 就有 5844）。
- 提量用**两遍 loudnorm**（先 `print_format=json` 测量，再 `linear=true` 带 measured_* 落地），比单遍动态模式不抽气：目标 I=-14 LUFS / TP=-1.0，实测 mean 从 -21.7dB 提到 -16.4dB。
- 音量关系参考：旁白 1.0 / BGM 0.34 / 引擎原声 0.20~0.55。

## 11. 卡拉OK字幕：libass 的两个坑（同为 2026-10-10 实测）

### 11.1 `\k` 的颜色约定与直觉相反
- **已唱 = PrimaryColour，未唱 = SecondaryColour**。设反的表现是"字唱完才变白"，看着像普通字幕。
- 用**最小样例**验证最快（别靠猜）：写一个 4 秒 ASS（`{\k100}AAA{\k100}BBB...`，Primary=白、Secondary=红），烧到纯色片上抽帧看谁先变色。
- 结论配置：`PrimaryColour=&H000B9EF5`（琥珀 F59E0B）、`SecondaryColour=&H00F8FAFC`（白），得到"未唱白 → 已唱琥珀"的扫过效果。

### 11.2 每行一个 `\k` 不是逐字
- `{\k18}整行文字` 只会整行一次性变色。要真逐字扫过需**逐字挂标签**，并把标点并入前一字（不单独计时）：
  `{\kf22}五{\kf21}次{\kf21}亚{\kf21}军，`
- 用 `\kf`（平滑填充）比 `\k`（硬切）观感更像卡拉OK。

## 12. HyperFrames 竖屏合成：时间轴与卡片（同为 2026-10-10 实测）

- **片尾黑屏**：素材轨总和 < 时间轴总长就会出现纯黑尾。**成片时长必须以素材轨为准**（`TOTAL = video_track_total`），或把最后一镜加长覆盖到底。本次因此修了 4.2s 黑屏（最后一镜 3.5s→6.1s）。
- **卡片别压脸**：确认卡片覆盖窗口下**实际是哪个镜头**再决定位置（本次差点为一个只存在于自定义测试组合里的人脸把卡片下移；成片时间轴上该卡片其实压在行驶镜头上）。统一放上部 `top:200px` 最稳。
- **素材轨与音轨要分别设定**：只改音轨时**不要重渲视频**，用 `-c:v copy` 只换音轨（`-map 0:v:0 -map 1:a:0`），画质零损失、几分钟内完成；**加 `-shortest`** 防止音轨比画面长。
- **渲染速度实测**：98s / 1080×1920 / 30fps / `-q delivery` 全量约 **4.5 分钟**（此前 101s 约 4.5 分钟）——仍是"改模板先 5s smoke 验证"更划算。
- **改 CSS/布局后必须全量重渲**（只有换音轨才能 copy）。

## 13. 交付与流程纪律（本次踩到的新坑）

- **清理脚本别误删中间产物**：一次 cleanup 把 `final_subbed.mp4`（烧字幕母版）删了，导致后续换音轨失败。清理白名单要显式排除"还要用的中间件"。
- **生成 JSON 工件后立刻自检必填字段**：`script.json` 有两段漏了 `delivery_cues.provider_text`，TTS 跑到第 2 段才 KeyError 崩（已浪费一次 GPU 冷启动）。分段任务**先跑一遍字段清单校验**再进重流程。
- **读 JSON 用 `utf-8-sig`**：PowerShell `Out-File -Encoding utf8` 会加 BOM，`json.load` 直接读会报 "Unexpected UTF-8 BOM"。
- **IndexTTS 客户端的 auto 情感会覆盖 emo_alpha**：`apps/indextts-bridge/client.py` 在 `emotion="auto"` 时把 `emo_alpha` 硬编码为 0.6，与频道锁定的 0.325 不符 → 需要精确复刻参数时，按 `CALLING.md` 的桥协议`subprocess` 直连服务（`use_emo_text=True + emo_alpha=0.325`），并自己用 `lib.gpu_lock` 包住服务生命周期。
- **纯音乐蒙太奇 = 无可用转录**：源片只有开头 20 秒英文旁白时，脚本应以**简介文案**为事实来源（并明确"事实仅限简介"），画面定位改走逐段抽帧 + 视觉核验，别指望转录时间轴。
- **抖音成品包**：`video.mp4` + `cover.jpg`/`cover_alt.jpg` + `metadata.json`（标题/备用标题/简介/话题/AI 披露/**素材出处**）；抖音无 CLI 上传，交付后由用户手动发布。
