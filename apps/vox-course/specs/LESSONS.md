# VOX 科技/硬核课程管线：实战经验沉淀（LESSONS）

> **来源**：《Agent Harness 课程第 1 集》（全流程实战踩坑与调优）。  
> **适用管线**：`vox-course` / `bin/course.py`。  
> **用途**：后续任何智能体或开发者使用该管线生成视频时必读，严禁重蹈覆辙！

## 1. 核心四大铁律 (Iron Rules)

### 铁律一：文案必须严格去AI化与口播字词汉字化（38条 + 口播3条）
1. **清退书面翻译腔与假深刻词汇**：
   - 严禁出现：“本质上”、“决定到底”、“无可否认”、“众所周知”、“毫无疑问”、“值得注意的是”、“在这个背景下”。
   - 全部替换为一线工程师日常口吻：“说白了”、“干脏活累活”、“大家全被忽悠了”、“直接把遮羞布给扯了”。
2. **长句彻底粉碎**：
   - 单句字数严格控制在 **15~25 字以内**（绝对上限 ≤28 字）。
   - 每遇到逗号必须具备自然的 300~400ms 呼吸停顿感，保证听众能够轻松吸收信息密度。
3. **数字、年份、金额必须纯汉字口播化**：
   - **年份**：严禁写阿拉伯数字或无“年”字列表，必须全部写为中文读音：“二零二五年”、“二零二六年”（写“2025”可能被朗读引擎误读为两千零二十五或二十二十五）。
   - **金额与数量**：必须写为口播习惯词：“三百亿美金”（非 300 亿）、“一万八千个”（非 18000）、“大几万”（非 好几万或上万）。
   - **百分比**：“百分之九十五”（非 95%）、“百分之十二”（非 12%）。

---

### 铁律二：IndexTTS2 纯净克隆与稳态采样参数锁死
1. **模型版本与通道选择**：
   - 模型版本锁定为 **2.5**（`INDEXTTS_MODEL_VERSION=2.5`）。
   - **严禁无脑传入全平 `calm` 向量**：在 2.5 版本中强制全平向量可能导致语气生硬机械。
   - **采用纯净克隆通道**：`use_emo_text=False, emo_vector=None`，直接利用克隆参考音（`voice_ref`，如 `D:/index-tts/my_voice.wav`）本身的自然语调与起伏。
2. **采样参数锁定**：
   - 采样参数必须锁死稳态配置：
     ```python
     temperature = 0.65
     top_p = 0.75
     top_k = 30
     repetition_penalty = 5.0
     ```
   - 此配置已在多段长文本中验证：彻底杜绝吃字、末尾含糊、电音发飘与循环杂音。
3. **分段与 Seed 隔离**：
   - 每一幕独立合成（`s01.wav` ~ `s0N.wav`），使用 `seed = 42 + idx` 确保每段音频既具备音色一致性，又避免跨段伪随机碰撞。
   - 合成完成后用 `wave` 或 `ffprobe` 获取真实物理音频时长 `actual_duration`，反哺给时间轴。

---

### 铁律三：音画卡片、终端日志与印章文本 100% 咬合
1. **杜绝音画脱节**：
   - 画面上的卡片、数据标签、终端代码和印章，**严禁用旧版本文案或泛泛而谈的占位词**。
   - 台词提到什么核心概念，画面卡片就必须亮出对应的一模一样的关键词：
     - 台词：“套在模型外面的装具，也就是 Harness！” → 卡片必须大字写出 `Harness`，印章盖下 `HARDWARE READY`。
     - 台词：“在后台挂了一个常驻的 IPython 终端” → 终端标题必须写 `IPython Sandbox Runtime`。
     - 台词：“跳过了一万八千多个重复输入的 Token！” → 终端实时日志必须高亮打印 `[PROMPT_CACHE] 18,432 tokens hit`。
     - 台词：“吐纸奇慢的高级复印机” → 卡片必须大字列出 `高级复印机` 与 `4x 首字 / 1.12x 逐字` 性能对比。

---

### 铁律四：长驻无闪烁字幕引擎（Continuous Hold Engine）与自然意群切分
1. **痛点与翻车根因**：
   - 之前“字幕一闪就没有了、不会停留”的根因：原逻辑对每一句独立执行 `fromTo(#sub-box, opacity:0->1)` 和 `to(#sub-box, opacity:0)`，导致出场淡出动画与下一句进场冲突撕扯；短句（≤0.6s）刚进场 0.2 秒就被强制抹杀。
   - 句间 0.3s~0.5s 的正常换气停顿被错误地用来折叠字幕框，导致全片字幕条剧烈闪烁、晃动。
2. **长驻停留机制（Continuous Hold）**：
   - **底座全程稳如磐石**：在同一幕内连续语流中（间隔 < 0.25s），字幕底座悬浮卡片**全程持续显示在屏幕下方，绝不在句与句之间折叠淡出**。
   - **毫秒无缝切词**：前一句字幕持续停留在屏幕上供观众阅读，直到下一句台词开口的精确毫秒瞬间，通过 0.12s 的微动直接平滑更新文本。
   - **仅在换景与长停顿淡出**：仅在换幕转场或出现较长真实停顿（≥0.25s）时，字幕框才平滑收起，下一幕开始时优雅淡入。
3. **自然意群切分（拒绝 0.6 秒碎屑）**：
   - 严禁将短疑问词、助词切为独立分句（如孤立的 `该怎么改？` 或 `第三条路，`）。
   - 必须合并为完整语义短句，单条字幕字数保证在 **10~22 字**，屏幕停留时间 **≥ 1.8~5.2 秒**，保证观众充裕的阅读与理解时间。

---

### 铁律五：全局音频单轨预混烘焙架构（Audio Master Baking Architecture）
1. **痛点与翻车根因**：
   - 第一幕同时出现两个声音重叠（串音），以及后半段无语音或截断。
   - 根因：在 HTML 内部声明数十个独立的 `<audio>` 标签。Chrome / Playwright 在无头渲染模式下并行预加载所有音频，导致第 0 秒多个音频被同时触发播放，并在跨幕时发生竞争截断，音量被浏览器默认混音算法按比例严重衰减。
2. **解决方案**：
   - **严禁在 HyperFrames 内部声明多段散装 audio 标签**！
   - 必须在 Python 后端（`bake_audio_tracks`），使用 ffmpeg 将全片 12 幕独立旁白与物理音效（paper_slide, stamp_thud）按毫秒时序精准拼接烘焙为全局唯一的 `narration_master.wav` 与 `sfx_master.wav`。
   - HTML 内部仅保留 3 个全局顶层音轨（BGM、VO、SFX），彻底根除多轨竞争、重音、串音与音量衰减缺陷。

---

### 铁律六：自回归句尾退火拖音治理（Anti-Drawl Adaptive Pacing）
1. **痛点与翻车根因**：
   - 语音口播中“总有一句话突然放慢”。
   - 根因：IndexTTS2 自回归模型在合成包含英文缩写（NPM, Profile, RFC）或末尾短句时，自发触发了 EOS 退火拉长音，语速从正常的 4.8 字/秒骤降至 3.2 字/秒，产生极度明显的拖沓与僵死感。
2. **解决方案**：
   - 合成后必须通过 Whisper 字级别时间戳（word_timestamps）进行语速审计。
   - 凡是检测到单句语速偏离标准（< 4.0 字/秒）的偏慢末尾分句，自动采用 ffmpeg `atempo` 算法（1.25x~1.38x）做针对性无损平滑提速，并压缩句尾多余冗余静音。
   - 音色与音调保持 100% 纯净一致，口播节奏紧凑、连贯、专业。

---

### 铁律七：12 幕多态视觉排版体系（Polymorphic Layout Archetypes）
1. **痛点与翻车根因**：
   - “为什么画面还是一个模板”：全片套用同一张卡片排版，信息呈现扁平无趣，视觉疲劳严重。
2. **解决方案**：
   - 12 幕必须依据各幕的技术核心主题，深度定制 8+ 种截然不同的视觉多态排版：
     - **调查头条风**：警示胶带 + 核心问号 + 404 红色印章；
     - **全屏黑客 CRT 终端**：绿色荧光代码流 + 脉冲雷达 + 日志打字机；
     - **三联立体拼贴板**：装、改、开三路径并列立体折叠对比；
     - **两栏配置解剖**：Profile 隔离配置代码与右侧重点说明卡片；
     - **代码 Diff 对比视窗**：红绿整行整块增删覆盖对比；
     - **副本唤醒蓝图**：黄色斜切胶带 + 动态解封 disabled 示意；
     - **暗黑危机警报**：红黑警戒条 + 漏洞爆炸卡片；
     - **四阶梯安检门**：逐级点亮的安全自审步进流水线；
     - **终极速查底牌**：全套架构思维导图与下集预告。

---

### 铁律八：片尾节奏留白与下集钩子
1. **严禁台词念完立刻黑屏截断**！
2. 最后一幕末尾必须包含明确的**下集预告钩子（Next Episode Hook）**，并弹出专属下集预告展板与印章。
3. 台词念完后，画面必须至少定格 **3.5 ~ 4.0 秒**，同时伴随背景音乐（BGM）优雅线性渐弱淡出（Fade Out 至 volume 0）。

## 2. 视觉与动效规范 (VOX Aesthetic)

### 2.1 色彩系统
```css
--paper-cream: #F3ECE0;      /* 复古米黄纸张 */
--paper-white: #FAF8F2;      /* 报告高白纸张 */
--paper-dark: #16181D;       /* 工业暗色纸板 */
--paper-manila: #E6DBC6;     /* 牛皮纸档案袋 */
--ink: #181614;              /* 印刷油墨浓黑 */
--terminal-green: #00FF41;   /* CRT 终端荧光绿 */
--warning-orange: #FF5F1F;   /* 预警荧光橙 */
--deep-orange: #8C2A00;      /* 烧灼暗橙 */
--stamp-red: #B71C1C;        /* 官方核准印章红 */
--tape-tan: rgba(235, 218, 168, 0.72); /* 哑光封箱胶带 */
```

### 2.2 核心物理拟真组件
- **撕纸轮廓**：利用 30+ 顶点的 `clip-path: polygon(...)` 塑造不规则毛边。
- **固定构件**：黄铜大头针（`pin-brass`）、红色塑料别针（`pin-red`）、斜切封箱胶带（`tape`）。
- **荧光笔标注**：底层绝对定位带有 `scaleX(0) -> scaleX(1)` 展开动画的高亮条。
- **硬核印章**：粗边框、等宽无衬线字体、-8°~-20° 旋转倾斜、从 `scale: 2.5` 骤降到 `scale: 1.0` 的重击顿挫感（`ease: "power4.out"` 或 `"power3.out"`），伴随 `stamp_thud.wav` 音效。
- **环境质感**：顶部覆盖三层指针穿透图层：
  1. `grain`：SVG 噪声微粒（opacity 0.55）；
  2. `vignette`：暗角渐变；
  3. `scanlines`：CRT 4px 扫描线与局部 Glitch 频闪。

## 3. 渲染与视频压制规范

1. **主渲染输出（1080P FHD）**：

2. **超清重采样输出（4K UHD HEVC）**：
   - 目标规格：`3840x2160`，编码器：`libx265`，像素格式：`yuv420p10le`（HEVC Main 10）。

   - 音频编码：`aac -b:a 320k`。
   - 产物：`projects/<id>/renders/final_4k.mp4`。

## 5. 发布与成品包实战经验 (Package & Publishing Lessons)

> **教训来源**：用户明确要求“B站的标题，简介，标签不要分成多个文档，在一个文档就行”以及“你做的什么封面，就截了一张图，你看以前几集是怎么做的”。

### 5.1 单文档交付原则 (The Single-Doc Rule)
- **痛点**：拆分成 `title.txt`, `desc.txt`, `tags.txt` 会导致用户投稿时在多个窗口来回切换，体验极其碎裂低效；
- **规范**：成品包文案**严禁拆分为多个碎片文件**，必须统一整合输出为单个规范文档：`package/bilibili.txt`；
- **排版结构**：
  1. 顶部项目元信息（名称、规格、路径）；
  2. 一、视频标题（首选高点击冲突型 + 3款备选）；
  3. 二、视频标签（一整行逗号隔开，点击即可整行全选复制）；
  4. 三、视频简介（格式化排版，含精准分幕时间戳、核心论点、下集预告、课件互动、制作说明）。

### 5.2 封面规范：严禁视频随意抽帧，强制走 HyperFrames 专属设计引擎
- **痛点**：在 package 阶段用 `ffmpeg -ss 12.0` 简单抓取一帧视频画面当作封面，缺乏信息密度与品牌识别度，被用户严厉批驳。
- **规范**：
  1. **专用工具调用**：必须调用 `bin/make_cover.py --light`，基于 `templates/hyperframes-cover/index.light.template.html` 渲染；
  2. **公式化大标题**：采用 150px 超大字 `<动作> = <关键破局点>`，强化吸睛度与知识权威感；
  3. **硬件感三色胶囊**：红（`#E94560`）、蓝（`#6366F1`）、绿（`#34A853`）色块承载三大核心技术词汇；
  4. **全平台 5 比例封面矩阵（绝对禁止图像硬裁切，必须原生独立排版渲染）**：
     - **痛点与教训**：曾使用 PIL `crop()` 对 16:9 封面盲目居中裁切，导致 1:1、3:4、9:16 的大标题两端文字、三色胶囊和右侧能力光环大面积被切断，内容残缺不全，被用户严厉批评。
     - **核心铁律**：**严禁任何比例采用居中硬切**。每个比例必须拥有独立的视口 CSS 容器与原生自适应排版，调用 `hyperframes snapshot` 独立渲染原生矢量快照，保证 100% 内容完整无截断（统一保存在 `package/covers/`）：
       - `cover_16x9.png` (1920×1080)：B 站 Web/App 横屏主封面，横向通栏大标题（150px）、三胶囊居左、光环居右；
       - `cover_4x3.png` (1440×1080)：B 站动态与推荐流卡片，缩减横向间距，两端各留出 160px 安全边距，标题 116px；
       - `cover_1x1.png` (1080×1080)：B 站合集主图 / 微信方形分享图，标题双行堆叠（115px），三胶囊竖排与光环横向并列居中，方正紧凑；
       - `cover_3x4.png` (1080×1440)：移动端竖版卡片推荐流，竖向空间延伸，大光环居中（280px），下设三胶囊与核心架构说明卡；
       - `cover_9x16.png` (1080×1920)：手机全屏动态 / 竖屏小视频，满血竖屏海报级排版，大光环（310px）、大胶囊，附带四条打勾绿标核心架构清单卡。

### 5.3 真实时间戳动态回填 (Precise Chapter Timestamps)
- 简介中的时间轴（如 `00:00`, `00:24`, `01:36`）必须由管线根据实际音频生成的物理时长（`actual_duration`）精准计算并格式化为 `mm:ss`，禁止人工臆测或使用静态占位符。
