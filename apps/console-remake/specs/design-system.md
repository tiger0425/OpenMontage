# 深色控制台 · 设计系统白皮书（console-v1）

> 本文件是 `console-remake` 管线的**世界宪法**。所有分幕、元素、动效、字幕都必须服从本文件。
> 素材来源：参考片《Agent Harness explained in 8min》(Kai) 的逐帧设计分析（`projects/ref3/`）。
> 版本：v1 · 2026-09-14 · 适用于 1920×1080 横版。
> **v1.1 增补（2026-09-15）**：新增 §10「console-v2 · 界面零件与动作三纪律」（来源：AI LABS 8-repo 参考片分析，`projects/console-opencode-repos/artifacts/direction.md`）。

---

## 0. 世界定义（一句话）

**世界 = 一块深色开发者控制台（console / HUD）。**
画面上没有「幻灯片卡片」——所有元素都是控制台里的**仪表与控件**。
元素是"被画上去的"（画出描边、扫填格子、抽出箭头），不是"被摆上去的"（卡片+阴影）。

**世界观三律**：
1. **仪表律**：每个元素都要回答「它测量什么 / 它显示什么状态」，装饰性元素不存在。
2. **留白律**：敢空。单帧可有 40%~90% 的纯黑。第一帧几乎什么都没有是合法的、被鼓励的。
3. **呼应律**：关系不靠"连线+说明"，靠**同色跨空间呼应**与**发丝线分区**建立。

## 1. 色彩系统（语义色，非装饰色）

色彩不是审美选择，是**语义编码**。同一个颜色在画面任何位置出现，含义必须一致。

| Token | Hex | 语义 | 典型载体 |
|---|---|---|---|
| `--bg` | `#0A0C0E` | 画布（近黑，非纯黑） | 全局背景 |
| `--surface` | `#0F1418` | 控制台面板底 | 深色面板、网格单元底 |
| `--surface-2` | `#141A20` | 面板抬升 | 胶囊底、刻度槽底 |
| `--line` | `rgba(255,255,255,0.14)` | 发丝线 | 分区线、网格描边 |
| `--ink` | `#E9EDF0` | 主文字 | 标签、正文 |
| `--ink-dim` | `#7C8794` | 次级文字 | 来源行、注释 |
| `--red` | `#E5484D` | **问题 / 成本 / 系统侧** | 格阵占用、巨型数字、描边框 |
| `--red-bright` | `#FF5147` | 红色强调（数字、高亮框） | 巨数、高亮描边 |
| `--red-deep` | `#2A0D0E` | 深红面板底 | 成本/警示面板 |
| `--amber` | `#D9A62E` | **占用 / 预算 / 容量** | 格阵、刻度槽 |
| `--blue` | `#58A6FF` | **模型 / 查询侧** | 模型框、查询元素 |
| `--cyan` | `#3FD8C2` | **结果 / 输出侧** | 结果标签、完成态 |
| `--paper` | `#F1EBDF` | 米白纸面板底 | 引文/原文 |
| `--paper-ink` | `#191A18` | 纸上文字 | 引文正文 |
| `--paper-dim` | `#5C5A52` | 纸上次级文字 | 标题衬字 |

**红线**：
- 一帧内**至多两个语义色**作主角（第三个只允许小面积胶囊/描边出现）。
- 红色面积 < 25% 画面；琥珀只出现在格阵/刻度槽。
- 禁用渐变背景、霓虹辉光堆叠、玻璃拟态。辉光只允许"淡到几乎看不见"的 1 层。

## 2. 版面系统

- **舞台**：1920×1080，`--bg` 底。
- **舞台底纹（全片唯一底图，2026-09-15 新增）**：近黑底之上叠一层极淡的「操作台面」——
  64px 网格（白 3%）+ 256px 十字节点（白 6.5%）+ 边缘暗角（55% 处起渐变至 42% 黑）。
  由宿主 `#root::before` 统一绘制，**永远在内容之下**；各幕根背景必须透明（`background:transparent`），
  让全片透出同一张台面。除此之外，再禁任何贴图/纹理。
- **安全边距**：左右 120px、上下 80px（元素不出安全区；字幕条除外）。
- **全局 HUD 框架（每帧常驻，2026-09-15 新增）**：观众任何时候都要知道「讲到哪了」——
  - **顶栏**：左侧品牌（`AGENT HARNESS · 智能体运行框架`，等宽+Medium）+ 右侧章节指示
    （`CH 05 / 09 · 五、系统提示与上下文`，编号红色高亮，随片自动翻页）；下方 1px 发丝线贯穿全宽（y=76）。
  - **进度轨**（y≈962）：全宽 1px 暗轨 + 红色填充条（全程匀速 scaleX 0→1）+ 游标红点 +
    每章起点一枚 9px 刻痕。
  - **画框**：全幅 16px 内缩 1px 细框 + 四角 28px 框标（"监控画面"的框感）。
  - **颗粒层**：确定性噪声图（固定种子）叠于内容之上、字幕之下（opacity 0.05），统一材质。
  - 以上全部为**宿主级元素**（不随幕消失）；单帧内容区仍遵守留白律。
- **基准网格**：8px。坐标一律取 8 的倍数。
- **常用分区**（不是模板，是语法）：
  - 左文右数（纸面板 ↔ 数据面板）
  - 上下对峙（标签行 ↔ 格阵）
  - 中央孤岛（单组元素悬在空画面中央，用于钩子/收尾）
- **发丝线分区**：分区用 1px `--line` 竖线/横线，**禁止用边框把内容包起来分区**。
- **同色跨空间呼应**：左侧红色标签 ↔ 右侧红色格阵；上句蓝色框 ↔ 下句蓝色箭头。呼应色必须同 token。

### 字体系统中枢（三族制）

中文是这套世界的「齿轮」——三族分工，禁止混用：

| 族 | 字体（本机实装） | 用途 | 人物性格 |
|---|---|---|---|
| **无衬线** | `Noto Sans SC` / `Noto Sans SC Medium` / `Noto Sans SC Black` | UI 文案、胶囊、toast、字幕、中文标签 | 工程师的即刻效率 |
| **衬线** | `Noto Serif SC`（纸面正文）/ `Noto Serif SC SemiBold`（纸面强调） | 米白纸面板引文（文档感） | 官方文件的权威 |
| **等宽** | `Cascadia Mono` / `Cascadia Mono SemiBold` | 数字、来源行、时间码、拉丁标签；巨数字用 SemiBold | 控制台读数 |

**字重纪律**：
- 一帧内中文字重最多 2 级差（如 Medium + Black）。
- 强调词用 `Noto Sans SC Black`（`text` 元素 `bold:true`）；引文强调用 `**词**` 标记（自动切衬线 SemiBold）。
- 数字一律等宽；巨数字一律 `Cascadia Mono SemiBold`。
- 引文一律衬线——这是「深色里的那块纸」的一半对比度来源。
- 拉丁与中文混排的标签类文字用 `--font-label`（拉丁等宽 + 中文 Medium），避免两种气质硬撞。

## 3. 九大零件（全部零件，别无其他）

> 每个零件给出：用途 / 视觉规格 / 动效语法 / 机器字段（生成器 element type）。
> 动效默认时长与缓动见第 6 节。

### 3.1 空心描边框 `frame`
- **用途**：待填 / 对比 / 占位。**不是实心卡片**。
- **规格**：1.5~2px 描边，圆角 8px，内部全空（透出 `--bg`）；可带一枚小标签（mono、全大写、12~20px）挂在框内左上或框顶居中。
- **动效**：淡入 + 从 0.985 轻微放大（0.4s）；标签文字 0.15s 后淡入。
- **两框对比**：蓝框在左、红框在右，中间一条发丝竖线（参考片帧 2）。
- **机器字段**：`type:"frame"`, `x,y,w,h`, `color:red|blue|amber|neutral`, `label`, `label_pos:inside-top-left|top-center`

### 3.2 数据格阵 `grid`（招牌零件）
- **用途**：预算 / 配额 / 占用 / 上下文窗口——**按比例填充的网格单元**，像 token 计数器。
- **规格**：单元格 22~28px 方块 + 4~6px 间隙；底格 `--surface` + 1px `--line` 描边；填充格取语义色。
- **填充**：支持 `fill`（0~1 从左往右）或 `fill_rows`（自上而下行填充，参考片帧 6 琥珀阵）。
- **附属**：格阵上方可挂两枚胶囊（左红右灰，如「系统提示 / 你的实际代码」）；填充边界处可立一条白色发丝线。
- **动效**：格阵底格先淡入 0.3s；填充格**从左往右逐格扫填**（每格 0.22s，stagger 0.012s，总时长 ≤1.4s）；边界发丝线在扫填结束时立起。
- **机器字段**：`type:"grid"`, `x,y,w,h`, `rows,cols`, `fill`(0~1), `fill_color:red|amber|cyan|blue`, `anchor:left`, `label_left`, `label_right`, `divider:bool`

### 3.3 等宽胶囊 `pill`
- **用途**：状态 / 来源 / 标签 / 对比词组。
- **规格**：全圆角（999px）；高 44px（sm）/ 56px（md）/ 72px（lg）；内文字 mono 或等宽气质（拉丁全大写 + 0.08em 字距；中文用无衬线黑体）；左右内边距 = 高 × 0.55。
- **两态**：`solid`（`--surface-2` 底 + `--ink` 字）与 `outline`（语义色描边 + 同色字，内部透底）。对比词组默认「灰实心 → 红描边」。
- **动效**：淡入 + 6px 位移（方向由入场语境决定），0.35s。
- **机器字段**：`type:"pill"`, `x,y`(左上角), `text`, `style:solid|outline`, `color:ink|red|blue|amber|cyan`, `size:sm|md|lg`

### 3.4 发丝线 `hairline`
- **用途**：分区（替代边框）。
- **规格**：1px；`--line` 色；垂直或水平；长度自定。
- **动效**：从中心向两端生长（scale 0→1，0.25s）。
- **机器字段**：`type:"hairline"`, `x,y`, `len`, `orientation:v|h`

### 3.5 巨型数字 `bignum`
- **用途**：关键量级（红色 15×、比例、价格）。
- **规格**：字号 180~280px，字重 800，`--red-bright`（或语义色）；右上可带小角标（×、%、单位）；下方可有 24px 的 dim 副题。
- **动效**：数字**滚动计数**（0.7s，从 1 或 0 到目标）+ 0.92→1 轻微放大；不弹跳（最多 `back.out(1.2)`）。
- **机器字段**：`type:"bignum"`, `x,y`(中心), `text`, `sub`, `color`, `size`, `count:bool`

### 3.6 连接箭头 `arrow`
- **用途**：流程 / 因果（把两个胶囊串起来）。
- **规格**：1.5px 线 + 小箭头（8×8px 三角）；颜色随语义；直线水平/垂直/斜线皆可；可虚线（`dash`，用于"弱关联"）。
- **动效**：**从左端抽向右端**（stroke-dashoffset），0.35s；箭头尖最后 0.1s 淡入。
- **机器字段**：`type:"arrow"`, `x1,y1,x2,y2`, `color`, `dash:bool`

### 3.7 刻度槽 `slot`
- **用途**：进度 / 容量（胶囊里的竖条）。
- **规格**：胶囊形底槽（`--surface-2`，高 44~56px，全圆角）；内部竖条 4×22px 白色/语义色，均布；已占刻度 = 亮，未占 = 暗。
- **动效**：底槽先入；竖条逐格亮起（stagger 0.06s）。
- **机器字段**：`type:"slot"`, `x,y`, `w`, `ticks`, `filled`

### 3.8 米白纸面板 `paper`
- **用途**：引文 / 原文——**在深色里插一块纸**，强烈对比。
- **规格**：`--paper` 底 + `--paper-ink` 衬线文字（Noto Serif SC），圆角 6px，无阴影或仅 1px 冷灰描边；正文 30px / 行高 1.62；行内 `**词**` = 衬线 SemiBold 强调；可带：
  - 顶部 mono 小标签（如 `ANTHROPIC 官方指南`）做成红底白字小胶囊**压在面板左上角**（允许出血 12px）；
  - **红框高亮**：红色 2px 描边框套住某一行，可轻微旋转 -0.5°；
  - 页脚 mono 小字（来源 URL）。
- **动效**：整纸淡入 + 上移 14px 归位（0.45s）；正文行错峰 0.06s；高亮框最后 0.25s 画出。
- **机器字段**：`type:"paper"`, `x,y,w,h`, `header`(小胶囊文字), `lines:[...]`, `highlight`(行号或子串), `footer`

### 3.9 通知小卡 `toast`
- **用途**：事件 / 提示（系统消息、结论条）。
- **规格**：小尺寸卡片（320~420×72~96px），`--surface` 底 + 左侧 3px 语义色边条 + 1px `--line` 描边；标题 20px、正文 22px 内。
- **动效**：从右侧 10px 弹入（0.35s，`back.out(1.4)`），停留、按需淡出。
- **机器字段**：`type:"toast"`, `x,y`, `w`, `title`, `body`, `accent:red|amber|blue|cyan`

## 4. 辅助原语（低频，白名单内允许）

| 原语 | 用途 | 规格 | 动效 |
|---|---|---|---|
| `panel` | 仪表底板（衬在胶囊/巨数/B 组元素下的深色面） | `surface`（默认）或 `deep-red`（成本/警示底板）；1px 描边、圆角 6px、**无阴影** | 淡入 0.45s |

| `seal` | 红印章（收尾用，如 `2026`） | 旋转 -4°~-8° 的红底白字方章 88~120px | 缩放 1.4→1 盖章（0.3s，`back.in`）|

## 5. 留白纪律

1. 单帧内容簇 ≤ 2 个（一个主簇 + 一个辅助簇）。
2. 开场 10 秒内与收尾 5 秒内，画面元素 ≤ 3 个（近乎全空合法）。
3. **禁止**为了"填满"而加装饰。空白是这个世界的呼吸。
4. 元素间的距离要大：主簇之间 ≥ 200px；元素不与安全边距贴边（≥120px）。

## 6. 动效语法总表（GSAP，全部 seek-safe）

### 6.1 基础入场语法

| 动作 | 时长 | 缓动 | 说明 |
|---|---|---|---|
| 通用入场 | 0.35~0.5s | `power2.out` / `power3.out` | opacity + 6~14px 位移或 0.985→1 缩放 |
| 格阵扫填 | ≤1.4s | `none`（线性 stagger） | 逐格 opacity，stagger 0.012s（可调 `stagger`） |
| 数字滚动 | 0.7~0.9s | `power2.out` | 代理对象计数，settle 于目标值 |
| 连接件抽出 | 0.3~0.45s | `power2.inOut` | stroke-dashoffset（箭头/引线/括线通用） |
| 发丝线生长 | 0.25s | `power2.out` | scale 0→1（transform-origin 居中） |
| 盖章 | 0.3s | `back.in(1.6)` | scale 1.4→1 |
| 通用退场 | 0.25~0.35s | `power1.in` | **只淡出，不滑走** |
| 幕间呼吸 | ≥0.3s | — | 上一幕淡出后留一段近黑（敢空） |

### 6.2 动作动效库（动词 → motion，2026-09-15 新增）

**原则：台词里出现动词，画面里必须有对应的"动作"，不能只有"显形"。**
元素字段 `"motion": "<类型>"`（可与常规入场叠加），参数见括号：

| 台词动词示例 | motion | 参数 | 演法 |
|---|---|---|---|
| 跑 / 走过 / 拉近 | `travel` | `mdx/mdy`（起始偏移）、`motion_dur`、`travel_fade` | 从偏移位置滑入落位；一次性经过物结尾淡出 |
| 塞给 / 灌进 / 写进 | `push` | `push_at`（句内秒）、`mdx/mdy`（终点位移）、`push_scale` | 先显形，随后被推入目标方向并缩小消失 |
| 挪 / 移 / 推走 | `shift` | `shift_at`、`mdx/mdy` | 句内向一侧平移（`power2.inOut`） |
| 删 / 失效 / 划掉 | `erase` | `erase_at` | 显形后被压扁擦除（scaleX→0.15 + 淡出） |
| 漏 / 掉 / 流失 | `leak` | `leak_n/at/gap/dy` | 底边渗出小方块，错峰坠落淡出 |
| 叠 / 盖 / 压上 | `stack` | `mdy` | 从下方叠上来落定（带轻微过冲） |
| 变长 / 铺开 / 张开 | `grow` | `motion_dur` | 从左向右 scaleX 长出 |
| 否定（打不开/跑不了） | `strike`（文本） | `strike_at` | 先显字，随后红线从左划到右（禁用 text-decoration） |

**选择纪律**：一帧内动作 ≤2 个主角；动词动效必须发生在"台词说到该动词"的 0.5s 窗口内。

### 6.2b 语音驱动锚定（`at` 字段，2026-09-15 确立 · 最高优先级纪律）

**画面的每一个可见动作都必须能指出"它在演哪个词"。** 这是"看和听在一条线上"的保证：

- 元素不再用估出来的 `enter_offset`，改用 `"at": "<台词中的字或词>"`；
  装配器从 `artifacts/line_words.json`（`align` 阶段用 whisper 逐句对齐出的词级时间戳）
  查出该词被说出的时刻，作为元素的进场时间。
- 工作流：`synth` → `align`（121 句词级对齐，约 3 分钟）→ 写分幕时逐要素声明 `at`。
- 审片标准：任取一个动作，若说不出它对应哪个词/小句，视为不成立。
- 典型：s11l03「打不开仓库，跑不了**测试**」——"测试"胶囊在 `跑` 出口的瞬间冲刺、
  在"不了"时被弹回；s12l02「**说**『给我个文件』」——气泡在 `说` 出口时开始向壳滚动。

### 6.3 连接件（第四类零件，2026-09-15 新增）

**原则：元素不许"孤立漂浮"——凡有归属关系的元素，必须用连接件系住。**

| 零件 | 用途 | 字段 |
|---|---|---|
| `leader` 引线 | 把标签/注释系到被标注元素（工程图风）；默认 from=bottom → to=top，端部带刻度 | `from/to`（引用元素 id，自动测量）或 `x1,y1,x2,y2`；`tick`（默认开）、`dash` |
| `bracket` 括线 | 把一组元素横向括起（如"长在壳里的东西"括住四枚胶囊） | `x1,x2,y`；端部下折 9px（`up:true` 朝上） |
| `hairline` + `tick:true` | 尺寸线式的分隔线（两端带端刻度） | 既有 hairline 加 `tick` |

**使用密度**：每幕至少让一组元素产生"联系"（同色呼应 / 引线 / 括线 / 箭头 / 发丝线分区，
四选一以上），纯孤立显示的幕视为未完成。

**确定性红线**（HyperFrames 契约）：
- 只用 `gsap.timeline({paused:true})` + `window.__timelines["main"]` 同步注册；
- 禁 `Math.random` / `Date.now` / `repeat:-1`；禁动画 `display/visibility`；
- 变换元素必须是 block 级 + 有真实尺寸；装饰元素按峰值尺寸预留净空。
- 不在 `index.html` 内放 `<audio>` 播控逻辑——音频由 ffmpeg 烘焙成 master 轨，`<audio>` 仅声明。

## 7. 字幕规范（console 字幕条）

参考片无字幕条；本管线**默认开启**一条 console 气质的字幕条（需求方指定"两者都要"）：

- 位置：底部通栏，y = 976~1056（高 80px）；其上一条 `--line` 发丝线。
- 背景：`rgba(8,10,12,0.82)`（平面，非圆角卡片）；文字 `--ink` 34px，中文黑体、拉丁 mono。
- 左侧带一枚 mono 状态符（如 `//` 或 `▍`）与红色时间码（如 `02:14`），右侧为文本。
- 出现：对应旁白句开始 +0.05s；句间空隙 <0.25s 时保持不放；空隙 ≥0.25s 时淡出再入（0.15s）。
- 字幕文本 = 旁白文本**原样**（含术语保留写法）。
- 片尾最后一幕字幕讲完后，字幕条与画面同时淡出。

## 9. 机器契约（生成器字段映射）

`episode.json` 的 `scenes[].lines[].elements[]` 中的 `type` 取值即第 3、4 节字段：
`frame | grid | pill | hairline | bignum | arrow | slot | paper | toast | panel | text | source | seal`

- 坐标一律为 1920×1080 绝对坐标，取 8 倍数；
- `arrow` 用 `x1,y1,x2,y2`；其余元素面元用 `x,y` 左上角（`bignum` 用中心）；
- 入场时间由 `line` 的 TTS 实测时长驱动（句起即入），个别元素可用 `enter_offset` 微调；
- 所有颜色取第 1 节 token 名（`red/amber/blue/cyan/ink/paper`），不写 hex；
- `text` 元素支持 `bold:true`（切 Black 字重）、`mono:true`、`align:"center"`、`size`；
- `paper` 的 `lines[]` 支持 `**词**` 行内强调（自动切衬线 SemiBold），可与 `highlight` 重叠。

## 10. console-v2 · 界面零件与动作三纪律（2026-09-15 增补）

> 来源：AI LABS《8 Insane GitHub Repos》参考片（`projects/console-opencode-repos/`）。
> 目的：让"深色控制台"从**抽象仪表**走向**真实工具界面**——观众看到的是工具本身，不是符号。

### 10.1 色彩 v2（在 v1 语义色上扩权）

- **主强调色改为橙**：`--accent #E8823C` / `--accent-bright #FF9D57`（HUD 章节号、进度轨、字幕时间码、窗口描边焦点均用它）。
- 新增 `--green #3FB950`＝**通过/完成/正向**；`--card #11161B` / `--card-2 #171D24` / `--card-line` ＝卡片与窗口质地。
- 语义不变：红=错误/风险；琥珀=占用/高亮；蓝=模型/系统；青=输出结果。
- HUD、字幕条、底纹微光同步切暖橙（背景红微光 → 橙微光）。

### 10.2 七个界面零件（机器字段见 schema）

| 零件 | 用途 | 关键字段 |
|---|---|---|
| `win` 窗口 | 终端窗 / 浏览器窗 / 应用窗的 chrome（三色窗控点 + 标题或地址栏）；内容元素另叠其上 | `kind:browser|terminal|app`, `title`, `url`, `focus` |
| `term` 终端内容 | 命令行**逐字打出** + 输出行逐条落地 + 光标 | `cmd`, `prompt`, `out[]`, `type_speed`, `out_stagger` |
| `rows` 状态行面板 | 列表/清单/结论面板：行 → 状态点（ok/warn/err/busy）逐条点亮 | `rows[{text,tag,dot}]`, `title`, `row_h`, `stagger` |
| `repocard` 仓库卡 | GitHub 风仓库卡：仓库字形 + 名称 + 描述 + 语言点/星标 + 角标 | `name`, `desc`, `lang`, `lang_color`, `stars`, `badge`, `tone:accent` |
| `mark` 跟随标注 | 高亮块 `hl` / 下划线 `ul` / 圈选 `ring` / 划叉 `cross`——**随旁白逐个出现** | `kind`, `color`, `rot`, `draw_dur` |
| `bars` 对比条 | 量化对比（1500→600 tokens、成本对比、通过率） | `rows[{label,value,text,color}]`, `bar_h`, `stagger` |
| `shape` 图示原语 | CSS 手绘示意（画像/模型/设备/矢量图）：prim 分 stage 逐层构建 | `prims[{kind,x,y,w,h,r,fill,color,stage}]`, `stage_stagger` |

**使用纪律**：界面零件也要遵守 v1 世界观——**仪表律**（每个窗口/面板必须"在测什么"）、**留白律**（单帧 1 个界面 + 1~2 枚标注）、**呼应律**（同色语义）。

### 10.3 动作三纪律（对"撞一下没意义"的根治）

1. **连接性**：凡有归属/指向关系的元素，必须用连接件系住（`leader`/`bracket`/`arrow`/发丝线）。元素不孤立漂浮；"从 A 抽出一条线到 B" 本身就是最简单的叙事动作。
2. **状态语义**：动的本质是**亮起 / 暗淡 / 连通 / 切断 / 流转 / 落定**，不是物理拟物。
   - 想到"撞一下"时，改成：引线被**切断**（红 `mark--cross` 压线）/ 状态点**点亮**（rows dot）/ 高亮**扫过**（mark）/ 面板**逐条落定**（rows/term out）/ 数值**对比生长**（bars）。
   - 台词说到哪一步，哪一步的**状态**就改变（语音驱动 `at` 锚定）。
3. **节制**：一幕只讲一个结构。宁可少，不可碎。

### 10.4 三个招牌手法（参考片风格核心）

- **分阶段构建**：先骨架/轮廓，后内容，再状态点 —— 一层层"长出来"（`shape.stage_stagger`、`rows` 双段落定、`term` 逐字+逐行）。
- **跟随旁白标注**：`mark` 元素用 `at` 锚定到旁白词，旁白说到哪儿，标注画到哪儿。
- **平滑转场**：幕间用同一元素族的位置延续（窗口左移 → 腾出右侧舞台；面板缩入 → 变成卡片）。

### 10.5 与 v1 的关系

- v1 零件（frame/grid/pill/bignum/paper/toast/panel）**继续可用**，但主色从"红主导"降为"红=错误"；
- HUD 框架（§2）**保留**，主色换橙；字幕条保留；
- 圆角实心卡的禁令在 v2 中**有条件放开**：仅限 `win/rows/repocard/panel--card` 这类**工具界面**零件（它们模拟的是真实软件窗口，不是 PPT 卡片）；`frame` 仍是空心描边，禁止"圆角卡+投影"的装饰性堆叠。

### 10.6 语义一致性纪律（第一纪律，2026-09-15 用户确立）

**先理解内容，再生成画面；画面必须能复述台词。**

- 写每一句的画面之前，先把台词拆成三样：**主体**（说的是什么）＋ **状态**（它处于什么状态）＋ **关系**（和谁相连）。
- 画面只演这三样；演不出来就说明没理解，不许"找个动作凑"。
- 反例（已被用户驳回）：
  - 「很平」→ 画成"空缺框"：错。正确是"**东西在，但它是平面的**"（静态图 + 不能转的标注）。
  - 「生成立体模型」→ 用平面示意：错。必须真的立体（CSS 3D 六面体 + 透视 + 旋转）。
- 自检问句（每幕必答）：
  1. 这句台词的主体是什么？我画的是它吗？
  2. 它的状态是什么？画面能看出这个状态吗（而不是它的反面）？
  3. 把这个动作/元素拿掉，意思会变吗？不会变 = 装饰，删。

### 10.7 真实素材与能力面（v2.2，2026-09-15 用户确立）

- **真实实体 → 真实素材**：真实存在的人物/产品/项目/界面/地点，必须用 `image` 零件
  （真实图片，放 `assets/images/`）或 `footage`（真实录屏）承载，并登记 `provenance`
  （url+license；自产填 `self`/`自有素材`）；禁止 CSS 假扮真实实体（`real:true` 校验），
  禁止 AI 生图编造真人/真实产品（封面除外）。抽象概念/结构/数据继续用九零件 CSS。
- **能力面纪律**：动笔前必做 HyperFrames 能力侦察（catalog/docs/media-treatment）并产出
  `artifacts/capability_recon.json`（积木↔分幕映射）；"能用没用上"按缺陷处理。
- 路由表与操作细节见 `.agents/skills/console-remake/SKILL.md` §8/§9；
  实战记录见 `LESSONS.md` §12。
